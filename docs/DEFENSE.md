**一句话定位**：把"医生问诊"变成一个可复现、可打分、可接强化学习的**环境**，而不是一堆调 API 的角色扮演。

### 2）实习期间的工作职责

按"我负责什么模块、交付物是什么"说，不要说"参与项目开发"。

1. **环境与奖励设计**：定义 ASK / EXAM / KNOWLEDGE / FINAL 四类动作协议、信息分级披露、
   逐轮即时奖励与终止奖励（诊断 0.5 / 治疗 0.3 / 安全 0.2，成本按 1 元 = 0.001 折算）。
2. **数据合成管线**：生成 → 审查 → 重写 → 评判四步，标签分层采样、分片与断点续跑、多裁判投票。
   论文侧数据集经该管线从 MIMIC-IV-NOTE 出院记录构建（授权由团队取得）：48,803 条病例
   （训练 34,160 / 验证 7,320 / 测试 7,323），基准 1,000 条从测试集按难度分层抽取；知识库 371,550 条 QA。
3. **评测体系**：三维度 1-5 分评分（≥4 计为正确）+ 效率统计 + 费用估算（价格清单三级匹配，未命中时模型兜底生成并回写清单）。
4. **训练接入**：把环境注册进 ms-swift，实现 5 个 ORM 奖励函数，写出 GRPO 启动脚本与多卡 accelerate 配置。
5. **可用性交付**：`cli.py` 六个子命令 + 零依赖 WebUI + 会话级 HTTP API + 离线过程可视化
   （`scripts/visualize_process.py`，mock 数据生成逐轮轨迹网页），让非开发者也能跑通一个病例。

### 4）实习工作内容与论文的相关性

**直接成果**：实践项目是论文 MedCPEnv 的工程底座——动作协议、纯函数奖励、数据合成管线与评测体系
构成论文方法与实验的实现部分；本人为共同第一作者，训练实验依托团队算力与数据授权完成。
论文只表述为"形成论文"，**不展开 venue 与审稿状态**。

**学位论文**：统一口径"受约束 agent 的评测与 RL 基建"。

- 学位论文做的是 LLM 越狱/红队：需要**可控环境、可复现轨迹、细粒度奖励**来量化"模型在什么约束下会越界"。
- 实践项目把同一套方法论落到医疗域：禁忌违反 ≈ 安全约束被突破，`avoid` 列表 ≈ 攻击成功判据，
  三维度打分 ≈ 攻击成功率的分解指标。
- 可迁移的具体件：`rewards.py` 的纯函数奖励、`env.py` 的动作协议与终止判定、`judger.py` 的
  规则降级（LLM 判分失败时退化为字符串匹配）——这套"规则打底 + 模型增强"的评测骨架在两个课题里通用。
- **不要说**"学位论文依赖本项目"：学位论文不依赖本项目数据，两者是方法论同源、课题独立。

### 5）实习工作对实验室可能的贡献

1. **一个能直接复用的环境模板**：换掉病例目录和动作集，就是任何"受约束多轮决策"任务的训练环境；
   环境与训练框架解耦（62 行插件），实验室其他同学接 ms-swift 不用改本体。
2. **一套评测口径**：三维度 + 效率 + 成本，附"两套评分不能混表"的口径说明（`docs/LEADERBOARD.md`），
   避免后续同学拿不同 Judger 版本的分数互相比较。
3. **一个低成本起步点**：6 个 mock 病例 + 离线剧本医生，新同学 `pip install` 后十分钟内能跑出第一张分数表，
   不必先申请 API Key 或等 GPU。
4. **可复现的演示**：答辩/组会现场不需要联网，一条 `sweep` 命令出对比表，过程可视化页直接打开就能讲轨迹。

## 3. 现场演示（90 秒，三条命令 + 一个备用页）

```bash
# ① 列病例：证明有跨科室覆盖
python scripts/cli.py cases

# ② 回放一条完整轨迹：讲逐轮奖励与终止四维拆解
```

④ 过程可视化：直接打开预生成的 `docs/process_demo.html`（agent loop 逐轮轨迹 + 多维反馈 + 结论对照）；

演示前先跑一次 ③ 确认 8000 端口可用；无网络的会场也能跑（WebUI 与可视化页只依赖标准库）。

## 4. Q&A 预案

**Q1：这个项目和你学位论文什么关系？**
A：方法论同源、课题独立。学位论文研究越狱攻击与防御，需要可控环境和细粒度奖励来量化"约束被突破"；
本项目把同一套环境/奖励/评测骨架落到医疗域，禁忌违反就是安全约束被突破的一种实例。学位论文不依赖本项目的数据。

**Q2：代码都是你写的吗？**
A：32 次提交全部是我：`jiazixiao.jzx` 27 次、`JZAO20L` 5 次（同一人的两个账号，后者为本机账号）；仓库从 v3.0 起由我独立维护。
（如果团队有他人参与，此处必须补一句边界，**不要含糊**。）

**Q3：1,000 条评测的数据哪来的？可信吗？**
A：病例经四步管线从 MIMIC-IV-NOTE 出院记录构建（数据授权由团队取得），48,803 条按难度分层切分，
基准 1,000 条从测试集抽取，另经人工抽样审核。可信度有两个已知限制，我主动说：
① 合成构建不能替代真实病历的全部复杂性；② 评分器换版本会改变绝对分（原始评分与 rejudge 两套口径差约 10 个百分点），
所以我只做**同表内相对比较**，不做跨表比较。

**Q4：强化学习训练有效果吗？**
A：论文报告了 Qwen3-4B 上的 GRPO 结果：base 综合 2.97，四种奖励配置全部超过 base，
medical-only 最优 3.14（诊断 26.0% → 31.2%）；efficiency-cost 组合反而把诊断压到 23.8%，
是效率-成本联合压力导致过早终止的奖励黑客现象。训练依托团队算力与数据授权完成，
我负责环境、奖励与评测的设计与实现；公开仓库尚未独立复现训练过程，这是下一步。

**Q5：为什么不用真实医院数据/真实医生参与？**
A：论文侧数据正是 MIMIC-IV-NOTE（团队授权）；公开仓库受 PhysioNet 许可限制只分发 6 个 mock 病例。
数据源可插拔（`assets/mock` 与 `data/` 同一套 schema），接入真实数据是工程配置问题，不是架构问题。
论文另有 50 例专家参照子集（人类专家综合 4.01 vs GPT-5.4 同子集 3.74）与 200 例专家校验集。

**Q6：这算科研还是工程？**
A：工程为主、方法为辅。可交代的工程判断有三处：动作协议选 XML 而非 JSON（模型遵循率更高）、
奖励用纯函数而非模型打分（训练时零 API 依赖、可单测）、成本用价格清单匹配而非 RAG 定价（少一个服务、可自举积累）。

**Q7：最大的坑是什么？**
A：成本口径。最初用检索式定价，需要额外维护向量索引；后来改成清单三级匹配 + 模型兜底回写，
既省一个服务，也让价格库随使用自动变全。这个取舍写在 `v0_5.md` 第 12 节。

**Q8：你和 MedCPEnv 论文是什么关系？**
A：实践项目是论文的工程底座，本人为共同第一作者，负责环境、奖励与评测的设计与实现；
训练实验依托团队算力与数据授权。论文状态不展开，只说"形成论文"。

## 5. 不要说的话（口径红线）

1. 不说"8 个模型中我们第一"——两套评分下排名不稳，只说"第一梯队"。
2. RL 数字必须带"论文报告 + 团队算力"出处，不冒认个人完成训练；不编论文里没有的数字。
3. 不说"真实医院在用"——目前是模拟环境；成本是代理估算，只用于相对比较，不说"能为病人省钱"。
4. 不把两套评分表混着引用；50 例专家参照子集是第三套口径，也不与 1,000 条表混取行。
5. 不承诺"可直接上临床"——定位是评测与训练基础设施。
6. 不展开论文 venue 与审稿状态——只说"形成论文 MedCPEnv（共同第一作者）"。
7. 演示轨迹分是环境纯函数规则分（0–1），论文基准是 LLM 判分（1–5）：不同量纲、不同对象，绝不混比；三档梯度仅作备用演示。
