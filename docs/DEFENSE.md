### 2）实习期间的工作职责

按"我负责什么模块、交付物是什么"说，不要说"参与项目开发"。

1. **环境与奖励设计**：定义 ASK / EXAM / KNOWLEDGE / FINAL 四类动作协议、信息分级披露、
   逐轮即时奖励与终止奖励（诊断 0.5 / 治疗 0.3 / 安全 0.2，成本按 1 元 = 0.001 折算）。
2. **数据合成管线**：生成 → 审查 → 重写 → 评判四步，标签分层采样、分片与断点续跑、多裁判投票。
3. **评测体系**：三维度 1-5 分评分 + 效率统计 + 费用估算（价格清单三级匹配，未命中时模型兜底生成并回写清单）。
4. **训练接入**：把环境注册进 ms-swift，实现 5 个 ORM 奖励函数，写出 GRPO 启动脚本与多卡 accelerate 配置。
5. **可用性交付**：`cli.py` 五个子命令 + 零依赖 WebUI + 会话级 HTTP API，让非开发者也能跑通一个病例。

### 4）实习工作内容与论文的相关性

**统一口径：受约束 agent 的评测与 RL 基建。**

- 论文做的是 LLM 越狱/红队：需要**可控环境、可复现轨迹、细粒度奖励**来量化"模型在什么约束下会越界"。
- 实践项目把同一套方法论落到医疗域：禁忌违反 ≈ 安全约束被突破，`avoid` 列表 ≈ 攻击成功判据，
  三维度打分 ≈ 攻击成功率的分解指标。
- 可迁移的具体件：`rewards.py` 的纯函数奖励、`env.py` 的动作协议与终止判定、`judger.py` 的
  规则降级（LLM 判分失败时退化为字符串匹配）——这套"规则打底 + 模型增强"的评测骨架在两个课题里通用。
- **不要说**"实践项目是论文的实验平台"：论文不依赖本项目，两者是方法论同源、课题独立。

### 5）实习工作对实验室可能的贡献

1. **一个能直接复用的环境模板**：换掉病例目录和动作集，就是任何"受约束多轮决策"任务的训练环境；
   环境与训练框架解耦（62 行插件），实验室其他同学接 ms-swift 不用改本体。
2. **一套评测口径**：三维度 + 效率 + 成本，附"两套评分不能混表"的口径说明（`docs/LEADERBOARD.md`），
   避免后续同学拿不同 Judger 版本的分数互相比较。
3. **一个低成本起步点**：6 个 mock 病例 + 离线剧本医生，新同学 `pip install` 后十分钟内能跑出第一张分数表，
   不必先申请 API Key 或等 GPU。
4. **可复现的演示**：答辩/组会现场不需要联网，一条 `sweep` 命令出对比表。

## 4. Q&A 预案

**Q1：这个项目和你论文什么关系？**
A：方法论同源、课题独立。论文研究越狱攻击与防御，需要可控环境和细粒度奖励来量化"约束被突破"；
本项目把同一套环境/奖励/评测骨架落到医疗域，禁忌违反就是安全约束被突破的一种实例。论文不依赖本项目的数据。

**Q2：代码都是你写的吗？**
A：28 次提交里 27 次是我的账号，另 1 次是我的另一个账号；仓库从 v3.0 起由我独立维护。
（如果团队有他人参与，此处必须补一句边界，**不要含糊**。）

**Q3：1,000 条评测的数据哪来的？可信吗？**
A：病例由四步管线合成（生成 → 审查 → 重写 → 评判，Judge 需 3/3 通过），评测集与训练集已切分。
可信度有两个已知限制，我主动说：① 合成数据不能替代真实病历，MIMIC 真实数据需授权后另行接入；
② 评分器换版本会改变绝对分（原始评分与 rejudge 两套口径差约 10 个百分点），所以我只做**同表内相对比较**，不做跨表比较。

**Q4：强化学习训练有效果吗？**
A：训练链路已完整打通（环境注册 + 5 个 ORM 奖励 + GRPO 启动脚本 + 多卡配置），
但**端到端的训练前后对比曲线还没有产出**，受算力与时间限制。这是本项目最明确的未完成项，
下一步是在 Qwen3-4B 上用 mock + 合成数据跑一轮 LoRA GRPO，给出训练前后的分数与成本对比。

**Q5：为什么不用真实医院数据/真实医生参与？**
A：真实病历涉及授权与脱敏（MIMIC-IV 需 PhysioNet 认证），本项目先解决"环境和评测口径"这一层，
数据源是可插拔的（`assets/mock` 与 `data/` 同一套 schema）。真实数据接入是工程配置问题，不是架构问题。

**Q6：这算科研还是工程？**
A：工程为主、方法为辅。可交代的工程判断有三处：动作协议选 XML 而非 JSON（模型遵循率更高）、
奖励用纯函数而非模型打分（训练时零 API 依赖、可单测）、成本用价格清单匹配而非 RAG 定价（少一个服务、可自举积累）。

**Q7：最大的坑是什么？**
A：成本口径。最初用检索式定价，需要额外维护向量索引；后来改成清单三级匹配 + 模型兜底回写，
既省一个服务，也让价格库随使用自动变全。这个取舍写在 `v0_5.md` 第 12 节。

## 5. 不要说的话（口径红线）

1. 不说"9 个模型中我们第一"——两套评分下排名不稳，只说"第一梯队"。
2. 不说"RL 训练提升了 X 分"——没有训练前后对比数据，不许编。
3. 不说"真实医院在用"——目前是模拟环境 + 合成病例。
4. 不把两套评分表混着引用（`docs/LEADERBOARD.md` 第 1 节已写明原因）。
5. 不承诺"可直接上临床"——定位是评测与训练基础设施。
